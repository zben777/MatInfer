从 LayerNorm 到 RMSNorm：归一化究竟改变了什么

一个 token 进入 Transformer 后，会被表示成一个隐藏向量。这个向量不仅有“各个特征是什么”的信息，还有整体数值尺度。Norm 做的事情，是先从向量中计算一个统计量，再调整向量的中心或尺度，让后续子层使用经过尺度控制的表示。

理解 Norm 需要连起来看三个问题：它对哪些元素统计，为什么选择这个统计量，以及调整以后保留了什么信息。 本文用四张图串起这些问题，再用同一组数字走完 LayerNorm 和 RMSNorm 的计算。

1. 先确定范围：对一个 token 的哪些数做归一化

图 1　典型 Transformer 的 Norm 对每个 token 的隐藏维度独立计算统计量。图下方示意一个 Pre-Norm 子层；一个 Block 的 Attention 和 FFN 通常各有自己的 Norm。

假设输入形状是 [B, S, D]：B 是批次大小，S 是序列长度，D 是隐藏维度。本文使用 normalized_shape=D，于是每个 [b, s, :] 向量单独做归一化。它不需要先把不同 token 或不同请求的数据合起来统计；同一模块的可学习参数则在这些位置共享。3

例如输入是 [2, 3, 8]，就有六个长度为 8 的向量。LayerNorm 为每个向量计算自己的均值和方差，RMSNorm 为每个向量计算自己的平方均值；若启用逐元素仿射参数，每个模块的 γ 有 8 个元素，LayerNorm 的 β 也有 8 个元素，而不是每个 token 都单独存一组参数。

1.1 尺度变化，为什么会影响后面的计算

先暂时去掉 Norm，考虑同一个向量 x 与放大后的 10x。对于没有 bias 的线性层，(10x)W = 10(xW)。如果 Q 和 K 都来自整体放大 10 倍的隐藏表示，它们的点积就会放大 100 倍。除以 √dₕ 并不能抵消这种输入尺度变化：√dₕ 处理的是头维度，输入幅值是另一个因素。

这里假设同一 Attention 子层的 Q、K 输入都被统一缩放，投影无 bias，且没有额外的 Q/K 归一化。这是解释尺度影响的简化模型；不能把它直接套到已有历史 KV Cache、只变化当前 Query 的情况。

看一个更小的 Softmax 例子：logits 为 [0, 1] 时，两个权重大约是 [0.269, 0.731]；把 logits 放大为 [0, 4]，权重变成 [0.018, 0.982]。即使两个分数的大小顺序没变，模型分配注意力的方式也明显改变了。 因而控制输入尺度并不只是防止溢出，它还影响实际计算的行为。

残差相加使隐藏状态在层间不断变化，各子层输出的尺度也可能不同。Norm 为子层提供一个更受控的输入，但数值是否稳定还与残差结构、权重、Norm 位置和计算精度相关。不能简单描述成“层数一多，数值就必然爆炸”。

1.2 在 Pre-Norm Block 中，它控制哪一段

图 1 展示的是一个子层。展开一个典型 Pre-Norm Block，就能看到 Attention 和 FFN 前各有一次 Norm：

两个 Norm 各自有自己的参数。Attention 读取 Norm₁(xₗ)，FFN 读取 Norm₂(uₗ)；残差支路则分别保留 xₗ 和 uₗ。归一化的是进入子层的那份表示，残差相加后的表示并没有被强制归一化。 所以不能由“每层都有 RMSNorm”推出每层 hidden state 的 RMS 都相同。

Post-Norm 则把 Norm 放到相加之后，例如 u = Norm(x + Attention(x))。两者改变了前向数据路径和反向梯度路径，不只是把图中的框移动一下。本文沿 Pre-Norm 解释数据流；训练行为的系统比较可进一步阅读 Pre-Norm / Post-Norm 分析。2

1.3 推理时不训练，为什么还需要 Norm

固定的是可学习参数 γ、β，不是当前输入的统计量。每次前向时，Norm 仍根据当前 token 的向量计算均值、方差或平方均值。新的 token、新的层输入都会带来新的统计量。

LayerNorm 和标准 RMSNorm 不依赖 BatchNorm 式的 running mean / running variance，在训练和推理时使用同一种按当前输入计算统计量的规则。1 所以 Norm 在推理中既不能直接删除，也一般不能像使用固定统计量的 BatchNorm 那样整体折叠成一个固定线性层。γ 的静态缩放是否可吸收到相邻权重中，是另一个与结构和精度有关的问题，不能因此省掉输入相关的归一化。

2. 两条计算路径：减去均值，还是只缩放尺度

图 2　LayerNorm 先中心化再按标准差缩放；标准 RMSNorm 直接按均方根缩放。图中的统计量是每行一个标量，γ 和 β 是沿隐藏维度的向量。

这里的均值、方差是在一个 token 的 D 个特征坐标上计算的，不是先收集大量样本再拟合概率分布。各坐标对应不同特征，也不需要假设它们独立同分布；这些统计量只是从整行提取中心和尺度的办法。

2.2 RMSNorm：直接衡量这一行的整体大小

RMSNorm 不关心“离均值多远”，而是关心“离零有多远”。直接求均值不适合衡量大小：[−2, 2] 的均值是零，元素却并不小。先平方可以避免正负抵消，再取平均，避免统计量仅因元素数量更多而变大；最后开平方，让分母回到与输入相同的尺度。

为什么开平方很关键？若输入放大 a 倍，平方均值会放大 a² 倍，均方根在 a 为正时放大 a 倍。因此用 RMS 作分母可以抵消整体的正比例放大。若直接除以平方均值，输出反而随 a 增大而缩小，得不到同样的尺度性质。

一个直观的边界例子是 [3, 3, 3, 3]。LayerNorm 的中心化结果全为零，正的 ε 保证计算有效，最终输出就是 β。RMSNorm 在 ε＝0、γ＝1 时输出 [1, 1, 1, 1]。共同偏移在 LayerNorm 中被移除，在 RMSNorm 中被保留。

省略中心化减少了数学步骤，但“中心化是否有必要”是模型设计与任务相关的问题。RMSNorm 原论文提出并实验考察了去掉中心化的方案；不能由此推出任意模型都可以无损替换 Norm。5

2.3 已经归一化，为什么还需要 γ 和 β

统一控制尺度，不代表所有特征都应该使用相同的最终幅值。γ 为每个特征提供一个可学习权重：某个坐标可以被放大，另一个可以被抑制；β 则提供逐特征偏置。它们是模块参数，在不同 token 间共享，不是根据每次输入临时求出的统计量。

例如归一化结果是 [0.6, 1.2]，γ 是 [2, 0.5]，乘完得到 [1.2, 0.6]。这时元素比例和整行 RMS 都变了。因此“RMSNorm 保留向量方向”说的是乘 γ 之前的归一化步骤；完整 RMSNorm 使用逐特征 γ 后，一般不再保持方向。

γ、β 也不能恢复归一化已经移除的所有输入信息。在 ε＝0 的理想条件下，x 和 10x 可以得到同一个归一化结果；再施加相同的固定参数，仍然无法区分它们。Pre-Norm 中残差支路保留原始表示，是理解整个 Block 时不可忽略的一部分。

2.4 ε 对小输入究竟做了什么

ε 加在平方尺度上，经过开平方后才成为实际分母的一部分。以常量向量 [a, a] 的 RMSNorm 为例，单位 γ 下每个输出是 a / √(a² + ε)。当 a＝0 时输出为零，不会出现 0 / 0；当 ε＝10⁻⁶、a＝10⁻³ 时，输出约为 0.707；a＝10⁻⁶ 时，输出约为 0.001。

当平方均值远大于 ε，归一化接近理想的尺度抵消；当它远小于 ε，输出近似为 x / √ε，表现为有限的线性缩放。这解释了为什么极小输入的 RMS 不会被强行变成一，也说明 ε 的取值会影响具体数值，不能只把它看成一个永远可忽略的补丁。

在尚未乘 γ 时，RMSNorm 对整行统一缩放，保留向量方向和非零元素之间的比例。LayerNorm 把中心搬到零，通常改变向量方向。这些是几何变化，不意味着输出被转换成高斯分布；归一化不会自动改变数据为某种指定的分布。

本例 LayerNorm 输出对称，是因为输入本身关于 4.5 对称。均值为零不意味着元素必须成对对称。 比如 [0, 0, 3] 的中心化结果是 [−1, −1, 2]，均值为零却不对称。

“归一化为 1”说的是哪个量

在本节的理想条件下，LayerNorm 的输出均值为零、方差为一；RMSNorm 的输出 RMS 为一，其均值约为 0.891，并不是零。

RMSNorm 输出的欧氏长度也不是一。因为平方均值是一，所以平方和为 D，长度为 √D；本例长度是 √8。使用正的 ε 后，归一化中间结果的平方均值为：

如果给所有元素加上 10，会怎样

LayerNorm 的均值从 4.5 变为 14.5，每个元素减去新均值后仍得到原来的偏差，因此输出不变。RMSNorm 不移除共同偏移，输入方向和平方均值都变了，输出一般也改变。

如果给所有元素乘同一个正数，在 ε＝0 且分母非零时，两种 Norm 的缩放都被分母抵消。ε 非零时通常只有近似的尺度不变性，尤其在输入很小时，不能忽略 ε 的影响。这个对比比简单记忆“一个控制方差，一个控制幅值”更能说明二者的边界。

4. 从公式到代码：归约、缩放与实际访存

图 4　四个方块表示逻辑依赖，不表示必须启动四个 kernel。融合实现可以把多个步骤放进同一个 kernel。

一行输入有 D 个元素，平方均值却只有一个数。这种“多个元素汇总为少量统计量”的操作叫归约（reduction）。rsqrt(q + ε) 得到分母的倒数，随后把同一个系数广播给整行每个元素，再乘各自的 γ。数学上等价于逐元素除以平方根，但实现可以把除法变成共享系数的乘法。

LayerNorm 还涉及均值与中心化，但高性能实现可以联合计算统计量，或使用 Welford 等算法。公式中先均值、后方差，并不规定必须启动两个独立 kernel；图 4 的四步也不规定 RMSNorm 必须读四遍 HBM。

对 [B, S, D] 输入，mean(dim=-1, keepdim=True) 的输出形状是 [B, S, 1]。广播后，同一行的 D 个元素使用同一个统计量，其他行使用自己的统计量。γ、β 的形状是 [D]，广播时在所有 token 位置共享。下面代码直接对应这个过程：

import torch


def layer_norm_steps(x, gamma, beta, eps=1e-6):
    # 先提升精度，再计算平方；低精度输入使用 FP32 统计量。
    work = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
    mean = work.mean(dim=-1, keepdim=True)
    centered = work - mean
    var = centered.square().mean(dim=-1, keepdim=True)
    normalized = centered * torch.rsqrt(var + eps)
    return (normalized * gamma + beta).to(x.dtype)


def rms_norm_steps(x, gamma, eps=1e-6):
    work = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
    mean_square = work.square().mean(dim=-1, keepdim=True)
    normalized = work * torch.rsqrt(mean_square + eps)
    return (normalized * gamma).to(x.dtype)


x = torch.arange(1, 9, dtype=torch.float64)
gamma = torch.ones_like(x)
beta = torch.zeros_like(x)

# eps=0 只复现本文非退化输入的手算；函数默认使用正的 eps。
print(layer_norm_steps(x, gamma, beta, eps=0))
print(rms_norm_steps(x, gamma, eps=0))

这不是优化 kernel，也不模拟所有模型的精度转换顺序。模型可能在乘 γ 前或后转换 dtype，舍入结果会因此不同；本文代码选择在统计量和仿射运算之后转换回输入 dtype。

为什么先提升精度，再平方

平方可能放大数值范围，归约又会累积许多项。若先在 FP16 中平方，溢出已经发生，之后再转 FP32 也无法恢复。将输入先提升到 FP32，可以改善这类统计计算的数值行为，但仍不意味着任意范围的输入都不会溢出。

为什么它常被当作访存优化对象

RMSNorm 对每个输入元素进行平方、归约贡献和少量乘法，计算量随 D 线性增长。相比高复用的 GEMM，它通常没有那么多计算可以摊薄数据搬运成本。假设一行 FP16 输入，单是读 x、写 y 的逻辑数据量就是 2D + 2D = 4D 字节；D＝4096 时是 16 KiB，此外还要读取 γ。

这只是逻辑数据量，不是实际 HBM 流量：γ 可能命中缓存，输入可能重新读取，未融合的表达式还可能读写中间张量。融合可以减少中间张量与启动开销；如果把残差相加也融合进 Norm，还可能减少相邻算子之间的中间读写。具体收益需要结合实现测量。

不过，“RMSNorm 一定 memory-bound”仍然太绝对。小输入可能更受启动延迟影响，较大的隐藏维度涉及归约通信、寄存器压力与占用率，具体瓶颈依赖形状、硬件和实现。数学上少了一些步骤，也不能直接推断延迟会降低某个固定比例。

5. 面试与自测：能否解释这些边界

为什么 Transformer 常沿隐藏维度做 Norm？是否依赖别的 token？

本文配置为每个 token 的表示独立计算统计量，同时共享模块参数。它不依赖其他 token 的统计量；但 token 的表示本身可能已通过 Attention 包含其他位置的信息。不能把“Norm 不跨 token 归约”理解为整个模型的 token 相互独立。

RMSNorm 的输出均值为零吗？长度为一吗？

一般都不是。忽略 ε、使用单位 γ 且输入非零时，归一化结果的 RMS 为一，欧氏长度为 √D。它没有减去均值。加入 ε、逐特征 γ 后，需要重新分析最终输出的统计量。

LayerNorm 一定需要两个独立的归约 kernel 吗？RMSNorm 一定更快吗？

公式描述数学关系，不决定物理 kernel 的划分。统计量可以联合计算，归约和逐元素操作也可以融合。比较延迟时需要相同形状、精度、硬件和实现条件；本文没有给出 GPU 实测结果。

能否把已训练模型的 LayerNorm 直接换成 RMSNorm？

两者对共同偏移的响应不同，输出通常不同；原模型参数适配了既定的归一化形式。不能仅凭算子更简单就认定替换后效果不变，需要模型层面的评估。
