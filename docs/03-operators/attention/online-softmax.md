# Online Softmax：怎样分块计算，又得到完整的 Attention 结果？

算完一部分分数，能不能先把这一部分处理掉，再继续读下一块？如果可以，就不用一直保留整行分数，更不用保存整个 Attention 矩阵。

困难在于：Softmax 的每个权重都依赖整行的分母。后面的分数还没有读到，前面的权重就无法最终确定。

这篇从一个只有三个分数的小例子出发，逐步回答：为什么不能各块独立归一化、需要保留什么，以及新最大值出现时怎样修正已经算过的结果。讨论标准 Attention 的前向计算，不含 dropout。

## 1. 为什么需要分块计算？

Attention 的计算可以分成三个步骤：

1. Q 与 K 做点积，得到相关性分数 S，并应用缩放与 Mask。
2. 对 S 的每一行做 Softmax，得到权重 P。
3. 用 P 对 V 加权求和，得到输出 O。

```math
S=\frac{QK^{\top}}{\sqrt{d_h}}+M,\qquad P=\mathrm{softmax}(S),\qquad O=PV
```

这里 d_h 是 Query/Key 的头维度，M 是加性 Mask，可见位置为 0，不可见位置为负无穷。每个 Query 对应 S 的一行；这一行描述它与各个 Key 的相关性。

如果分开执行这三个步骤，典型实现会先将 S 写入显存，Softmax 读取 S 后再写出 P，最后读取 P 去乘 V。对于长度为 N 的完整自注意力，S、P 都是 `N × N`，序列越长，中间张量越大。

例如，N = 4096 时，每张 FP32 矩阵占 64 MiB；如果 S、P 同时完整保存，两张合计 128 MiB。这还只计算一个 batch 中的一个头。具体占用会随 dtype 和缓冲区复用方式变化，但它已经说明：**完整保存中间矩阵，代价可能很大。**

所以我们想换一种计算方式：每次只处理一小块分数，立刻把它对输出的贡献累积起来，随后复用这块空间。

> **分块的目标：处理完当前块后，留下少量足以合并结果的状态，而不是留下当前块的全部分数与权重。**

为了理解合并方法，接下来只看 Attention 矩阵中的一行。其他行使用同样的规则，这个例子不依赖特定的推理阶段。

## 2. 为什么不能每块分别做 Softmax？

设一行分数和对应的 Value 为：

```text
分数 s： [0, ln 2, ln 4]
Value：  [1,    3,    5]
分块：   └─ 第一块 ─┘ └第二块┘
```

真实的 Value 通常是向量。这里先用标量，方便把加权过程算清楚；向量情形对每个分量进行相同的累积。

三个分数取指数后是 `[1, 2, 4]`，完整 Softmax 的共同分母为 7。因此：

```math
P=\left[\frac{1}{7},\frac{2}{7},\frac{4}{7}\right],\qquad
O=\frac{1\cdot1+2\cdot3+4\cdot5}{7}=\frac{27}{7}
```

现在只看第一块。对 `[0, ln 2]` 单独做 Softmax，得到 `[1/3, 2/3]`；第二块只有一个元素，单独做 Softmax 得到 `[1]`。

直接拼起来，权重变成 `[1/3, 2/3, 1]`，总和为 2。即使再除以 2，让总和回到 1，也会得到 `[1/6, 1/3, 1/2]`，仍然不同于完整结果。

问题在哪里？第一块的指数和是 3，第二块是 4。它们在全局结果中应分别占 `3/7` 和 `4/7`，独立归一化却把每个块都变成了“总权重为 1”的一组数据，丢掉了块与块之间的相对分量。

局部输出也存在同样的问题：第一块的输出为 `7/3`，第二块为 5，简单平均得到 `11/3`，不是正确的 `27/7`。

> **局部 Softmax 可以算，但局部输出不能直接拼接、相加或平均。要正确合并，必须保留它对应的归一化信息。**

### 先留下分子与分母，最后再除

暂时不考虑指数溢出，这个例子其实很容易分块：第一块留下分母 3、加权分子 7；第二块留下分母 4、加权分子 20。最后分别相加，再做一次除法，就是 `(7 + 20) / (3 + 4) = 27/7`。

因此，分块合并的基本思路已经出现：**不要急着得到最终权重，而是先累积分母和输出分子。**

但是直接计算指数还有一个数值问题：分数很大时，指数可能溢出。解决这个问题，就需要第三个状态——最大值。

## 3. 新块出现更大的最大值，旧结果怎么办？

### 3.1 为什么要减去最大值？

稳定 Softmax 会先减去整行最大值 m，再计算指数：

```math
m=\max_t s_t,\qquad
p_t=\frac{e^{s_t-m}}{\sum_j e^{s_j-m}}
```

这样最大的指数项是 1，其他项不超过 1，避免直接计算很大的正指数。结果不变，因为分子、分母同时乘了 `exp(-m)`，这个共同因子会抵消。

于是，处理过一部分数据后，我们保留以下三个状态：

| 状态 | 含义 | 在合并中的作用 |
| --- | --- | --- |
| m | 已处理分数的最大值 | 指数计算的共同基准 |
| ℓ | 减去 m 后的指数和 | 最终归一化的分母 |
| U | 减去 m 后，指数权重乘 Value 的和 | 输出的未归一化分子 |

这里用 U 表示分子，用 O 表示归一化输出。若已经处理的 Key 集合为 A，三个状态满足：

```math
m=\max_{t\in A}s_t,\qquad
\ell=\sum_{t\in A}e^{s_t-m},\qquad
U=\sum_{t\in A}e^{s_t-m}V_t
```

读完整行后，输出就是 `O = U / ℓ`。单独计算 Softmax 的归一化统计量只需要 m、ℓ；为了直接得到 Attention 的 Value 聚合结果，还需要 U。

### 3.2 回到第一块：我们保存的数值变了

第一块的分数是 `[0, ln 2]`，最大值为 ln 2。减去它后，指数项从 `[1, 2]` 变成 `[1/2, 1]`。

因此，这一块的状态为：

```text
m = ln 2
ℓ = 1/2 + 1 = 1.5
U = 1/2 × 1 + 1 × 3 = 3.5
```

虽然分子、分母都变小了，它们的比值仍然是 `3.5 / 1.5 = 7/3`，与前面独立计算这一块的输出一致。

第二块到来时，我们看到了更大的分数 ln 4。新的最大值是 ln 4，而旧 ℓ、U 是以 ln 2 为基准算出来的。**两个块使用的指数基准不同，不能直接相加。**

### 3.3 换一个基准，是否必须重算所有旧分数？

不需要。假设某个旧分数为 s，旧指数是 `exp(s - m_old)`，换成新基准后：

```math
e^{s-m_{\mathrm{new}}}
=e^{s-m_{\mathrm{old}}}\,e^{m_{\mathrm{old}}-m_{\mathrm{new}}}
```

等式右边的第二项与 s 无关。也就是说，**每个旧指数都乘同一个系数**，就能换到新的基准。因此，不必保留所有旧分数，也不必重新计算每个指数，直接缩放已经累积的和即可。

在我们的例子里，这个系数为：

```math
\alpha=e^{\ln2-\ln4}=\frac{1}{2}
```

旧分母变成 `1.5 × 1/2 = 0.75`，旧输出分子变成 `3.5 × 1/2 = 1.75`。现在它们与新块都以 ln 4 为基准，可以相加了。

为什么 U 也必须乘这个系数？因为 U 只是每个指数项先乘对应的 V，再相加。所有指数项一起缩小一半，它们对 U 的贡献也一起缩小一半。V 本身并没有变化。

> **Rescale 修正的是指数的基准。分母 ℓ 与分子 U 都依赖同一组指数，所以二者必须一起修正。**

### 3.4 把这个过程写成通用的块合并公式

设旧状态是 `(m, ℓ, U)`，新块独立算出的局部状态是 `(m_b, ℓ_b, U_b)`。先选择共同基准，再分别缩放新旧状态：

```math
m_{\mathrm{new}}=\max(m,m_b),\qquad
\alpha=e^{m-m_{\mathrm{new}}},\qquad
\beta=e^{m_b-m_{\mathrm{new}}}
```

```math
\ell_{\mathrm{new}}=\alpha\ell+\beta\ell_b,\qquad
U_{\mathrm{new}}=\alpha U+\beta U_b
```

若新块最大值更大，α 会缩小旧状态；若旧最大值更大，β 会缩小新块状态；最大值相同则两个系数都为 1。每次合并后，m、ℓ、U 都再次描述“已经处理的全部数据”，所以下一个块可以继续使用同样的规则。

这就是 Online Softmax 中“在线”的含义：每来一块，就更新少量状态，无需等所有分数都到齐才能开始处理。[Online Softmax 原论文](https://arxiv.org/abs/1805.02867)讨论了在线维护归一化统计量；在 Attention 中，还要一起维护加权 Value 分子。

## 4. 完整算一遍，与一次性计算是否一致？

现在把同一个例子从头到尾连起来：

| 步骤 | 最大值 m | 分母 ℓ | 输出分子 U |
| --- | --- | --- | --- |
| 第一块 `[0, ln 2]` | ln 2 | 1.5 | 3.5 |
| 第二块 `[ln 4]` 的局部状态 | ln 4 | 1 | 5 |
| 第一块换到 ln 4 基准，乘 α = 1/2 | ln 4 | 0.75 | 1.75 |
| 合并两块，第二块 β = 1 | ln 4 | 1.75 | 6.75 |

最后除以分母：

```math
O=\frac{6.75}{1.75}=\frac{27}{7}\approx3.857143
```

这与第二节中一次性计算的结果一致。它不是这个例子的巧合：每次缩放都由指数恒等式保证，合并后保存的仍然是全部已处理位置的指数和与加权分子。

在实数运算下，分块改变了计算顺序，没有改变 Attention 的数学结果。浮点实现会受到求和顺序、精度和指数近似的影响，因此“数学等价”不意味着不同 kernel 的输出逐位相同。

### 这为什么能减少中间张量？

当前块的分数计算出来后，先得到指数项，再直接乘对应的 V，把贡献合并到 U。合并完成，旧块的全部分数与指数项便不再需要；它们的信息已经通过 m、ℓ、U 保留下来。

对每个 Query 行，长期保留的是两个标量和一个 Value 维度的向量，而不是全部 Key 对应的分数与权重。多行 Query 可以分别维护各自的状态。

> **Online Softmax 解决的是“分块后怎样正确归一化”。FlashAttention 再把分块 QK、归一化统计与乘 V 组织在 kernel 内，使完整 S、P 不必写入显存后再读回。**

这不要求实际使用场景只能是串行扫描：不同块也可以先独立算出状态，再按同样规则合并。怎样划分任务、怎样映射到 GPU，是后面的工程问题。

## 5. 对照公式看参考代码

下面的 PyTorch 实现支持一个或多个 Query 行。它直接以更新后的全局最大值计算当前块的指数，而不是先用块内最大值计算后再乘 β。两种写法等价。

读代码时，先看循环中的三个更新：**换最大值基准、更新 ℓ、更新 U**。Mask 的边界处理放在后面的补充里解释。

```python
import math
import torch


def online_attention(q, k, v, block_size, valid=None):
    # q: [B_r, d_h], k: [T, d_h], v: [T, d_v]
    if block_size <= 0 or k.shape[0] == 0:
        raise ValueError("block_size and context length must be positive")
    rows = q.shape[0]
    m = torch.full((rows,), -torch.inf, dtype=q.dtype, device=q.device)
    ell = torch.zeros_like(m)
    u = torch.zeros((rows, v.shape[1]), dtype=q.dtype, device=q.device)

    for start in range(0, k.shape[0], block_size):
        end = min(start + block_size, k.shape[0])
        scores = (q @ k[start:end].T) / math.sqrt(q.shape[1])
        if valid is not None:
            scores = scores.masked_fill(~valid[:, start:end], -torch.inf)

        block_max = scores.amax(dim=1)
        m_new = torch.maximum(m, block_max)
        # 尚未遇到有效 Key 的行，使用 0 作临时指数基准。
        # 被屏蔽分数仍为 -inf，其指数为 0，状态保持空。
        base = torch.where(torch.isfinite(m_new), m_new, torch.zeros_like(m_new))
        alpha = torch.exp(m - base)  # 空状态下 exp(-inf) = 0
        e = torch.exp(scores - base[:, None])
        ell = alpha * ell + e.sum(dim=1)
        u = alpha[:, None] * u + e @ v[start:end]
        m = m_new

    if torch.any(ell == 0):
        raise ValueError("each query must have at least one visible key")
    return u / ell[:, None]
```

当前块的 `e` 已经使用新基准，因此新块贡献可以直接相加。旧贡献仍使用旧基准，必须乘 `alpha`。循环结束后统一除以分母，与前面的推导一致。

这是数学参考代码：它调用多个普通 PyTorch 算子，并创建当前块张量，没有实现 FlashAttention 的 kernel 融合与片上数据流。输入要求 Q、K、V 在同一设备、同一浮点 dtype，元素有限；`valid` 为同设备布尔矩阵，True 表示可见。核对递推关系时可先使用 FP64。

## 工程补充：理解主线后再看这些细节

### A. 多行 Query 的 Shape 与广播

| 张量或状态 | Shape | 含义 |
| --- | --- | --- |
| Q_i | `B_r × d_h` | 当前 Query 行块 |
| K_j | `B_c × d_h` | 当前 Key 块 |
| V_j | `B_c × d_v` | 当前 Value 块 |
| S_ij、E_ij | `B_r × B_c` | 局部分数与未归一化指数项 |
| m、ℓ、α | `B_r` | 每行各自的统计量与修正系数 |
| U、O_i | `B_r × d_v` | 分子与最终输出 |

1. **归一化沿 Key 方向进行。** 每个 Query 行有自己的 m、ℓ、U，不能把不同行的分母混在一起。
2. **缩放 U 时需要广播。** `alpha[:, None]` 将每行系数作用于该行全部 Value 分量。
3. **指数项还不是概率。** E 尚未除以 ℓ，不能直接当作最终权重 P。
4. **最后一个块可以不满。** 只需确保每个可见 Key 被正确处理一次，不要求序列长度整除块大小。

### B. 初始化与全屏蔽行

初始状态为 `m = -∞、ℓ = 0、U = 0`。第一次读到有效分数时，旧贡献的修正系数为 0，新块建立第一个非空状态。

但如果初始块某一行全被 Mask 屏蔽，该行仍没有有效最大值。直接计算 `-∞ - (-∞)` 会得到 NaN，需要跳过空行更新，或使用安全的临时指数基准。

上面的代码使用临时基准 0，使全屏蔽分数的指数仍为 0，空状态不会产生贡献；已有有效状态的行遇到空块时，旧状态保持不变。最终若一整行都没有可见 Key，分母仍为 0，代码选择抛出异常。实际 kernel 应明确规定对应的输出策略。

### C. 状态存在哪里？是否减少计算量？

1. **数学状态不规定物理存放位置。** m、ℓ、U 通常映射到寄存器和累加器，K/V tile 等可能放 Shared Memory。具体布局取决于实现；寄存器不足导致 spill 时，状态可能产生额外显存访问。
2. **Shared Memory 不是全 GPU 的共享池。** 它受到 SM、CTA 资源限制，不能把各 SM 容量相加后供一个任意 kernel 使用。
3. **Dense Attention 的配对计算仍存在。** N 个 Query 与 N 个 Key 的主计算仍是 O(N² d_h)。分块减少完整中间矩阵的存储与往返，没有免除所有可见位置的点积。
4. **低精度需要单独考虑。** FP16/BF16 kernel 通常使用更高精度的归约与累积，指数近似、Tensor Core 布局和资源占用也会影响结果与速度。

### D. 在不同推理阶段怎样应用？

| 场景 | Query 数量 | 分数矩阵 Shape | 关注的工程问题 |
| --- | --- | --- | --- |
| 长度 N 的完整 prefill | N | `N × N` | 避免巨大中间矩阵、增加行块并行 |
| 单 token decode，T 个可见 Key | 1 | `1 × T` | 历史 KV 读取、任务数、分段归并开销 |

算法逐行成立，适用于两者。Decode 只有一个 Query，主计算本来就是 O(T d_h)，不能把它说成先构造 `T × T` 矩阵再通过 FlashAttention 变为线性。

Online Softmax 的小状态只是本次计算的累积状态，不会替代下一步需要的历史 K/V。它与用递归状态代替逐 token KV 的 Linear Attention 是不同思路。

### E. 显存占用的统计口径

前文的 128 MiB 假设一个头的 S、P 都以 FP32 同时完整物化；如果都使用 FP16/BF16，合计为 64 MiB。如果 dtype 不同或复用缓冲区，实际峰值也会改变。

单 Query 对 4096 个 Key 时，S、P 各为 `1 × 4096`，FP32 每张 16 KiB、合计 32 KiB。这里使用二进制单位：`1 MiB = 2²⁰ bytes`、`1 KiB = 2¹⁰ bytes`。

这些数值说明完整物化的代价，不意味着普通 Attention 会先把完整 S、P 塞进 Shared Memory。数据中心 GPU 常说 HBM；RTX 4090 使用 GDDR6X，涉及它时应理解为对应的显存访问。

## 面试问答

### 为什么不能每块独立 Softmax 后直接平均输出？

> 独立归一化把每块的总权重都变成了 1，丢掉了块与块之间的相对分量。合并时必须恢复全局归一化关系，需要最大值、指数和以及加权输出分子。

### 新最大值出现后，为什么旧分母与旧输出分子都要缩放？

> 所有旧指数都要从旧基准转换到新基准，统一乘 `exp(m_old - m_new)`。ℓ 是这些指数的和，U 是这些指数乘 V 的和，所以两者必须一起缩放。

### 只维护 m 和 ℓ，够不够得到 Attention 输出？

> 不够。它们保存归一化统计量，还要维护指数权重乘 Value 的分子 U，最终用 U 除以 ℓ，才能得到聚合输出。
