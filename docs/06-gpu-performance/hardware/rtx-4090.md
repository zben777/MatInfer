# RTX 4090：硬件参数与峰值算力口径

> 状态：官方规格已核对；尚未进行本机实测。核对日期：2026-10-05。适用于标准桌面 GeForce RTX 4090，不适用于 RTX 4090 D 或笔记本 GPU。Tensor 吞吐采用 NVIDIA Ada 白皮书 V2.02 的口径。

## 要解决的问题

学习推理性能之前，需要知道 GPU 的计算与显存带宽上限。RTX 4090 常见的 82、165、330、660、1321 等算力数字分别指什么？为什么同一张卡会有这么多“峰值算力”？

核心结论：**峰值算力必须同时记录执行单元、输入精度、累加精度、稀疏条件与频率口径。** 同样写成 TFLOPS，数字也未必能直接比较。

## 基础参数

| 参数 | 标准 RTX 4090 | 理解方式 |
| --- | --- | --- |
| GPU 架构 / 芯片 | Ada Lovelace / AD102 | 架构名称与芯片型号 |
| Compute Capability | 8.9 | CUDA 编译目标通常写成 `sm_89`；不是 CUDA Toolkit 版本 |
| 启用的 SM 数 | 128 | 完整 AD102 设计有 144 个 SM，4090 产品启用 128 个 |
| CUDA Core | 16384，平均每 SM 128 个 | 128 × 128 = 16384 |
| Tensor Core | 第四代，512 个，每 SM 4 个 | 128 × 4 = 512 |
| 官方 Boost Clock | 2.52 GHz | 官方计算峰值所用频率，实际运行频率会变化 |
| CUDA Core FP32 峰值 | 约 82.6 TFLOPS | 非 Tensor 路径，按 FMA = 2 FLOPs 计数 |
| 显存 | 24 GB GDDR6X | 容量与带宽是不同指标；4090 显存不是 HBM |
| 显存位宽 / 数据率 | 384 bit / 21 Gbit/s 每引脚 | 用于计算外部显存理论带宽 |
| 显存理论带宽 | 1008 GB/s，约 1.008 TB/s | 十进制单位；不同于实测有效带宽 |

硬件规格取自 [NVIDIA Ada 白皮书 Appendix A，印刷页 29–31](https://images.nvidia.com/aem-dam/Solutions/geforce/ada/nvidia-ada-gpu-architecture.pdf#page=29)。计算能力由 [NVIDIA CUDA GPU 列表](https://developer.nvidia.com/cuda/gpus)确认。

CUDA Core 是 SM 内的运算资源，不能理解成 16384 个独立 CPU 核，也不能把数量直接等同于同时驻留的线程数。Tensor Core 则服务于受支持的矩阵乘累加运算；CUDA 程序不会因为在 GPU 上运行就自动使用它。

## Tensor Core：密集与稀疏峰值

下表单位均为 **TFLOPS**，按官方 Boost Clock 计算。“结构化稀疏”列是满足硬件规定的稀疏模式时的有效算力口径，不能拿来当普通密集矩阵乘的上限。

| 乘法输入精度 | 累加精度 | 密集峰值 | 结构化稀疏有效峰值 |
| --- | --- | ---: | ---: |
| TF32 | FP32 | 82.6 | 165.2 |
| FP16 | FP16 | 330.3 | 660.6 |
| FP16 | FP32 | 165.2 | 330.4 |
| BF16 | FP32 | 165.2 | 330.4 |
| FP8 | FP16 | 660.6 | 1321.2 |
| FP8 | FP32 | 330.3 | 660.6 |

依据：[NVIDIA Ada 白皮书 V2.02，印刷页 30–31，表 2 与脚注](https://images.nvidia.com/aem-dam/Solutions/geforce/ada/nvidia-ada-gpu-architecture.pdf#page=30)。保留官方四舍五入结果，因此表中的 330.4 不改写成 330.3。V2.02 明确修正了 FP8 输入、FP32 累加的峰值；阅读旧资料时应核对这一项。

因此，初始笔记中的三项需要这样调整：

- “Tensor Core FP32 = 330 TFLOPS”：条件不完整。330.3 可以对应 FP8 输入、FP32 累加的密集路径，但不能称作完整 FP32 乘法的 Tensor 算力。TF32 输入也不等于完整 FP32 输入。
- “FP16/BF16 = 1321 TFLOPS”：不正确。FP16/BF16 输入、FP32 累加的密集峰值是 165.2 TFLOPS。FP16 输入、FP16 累加则是 330.3 TFLOPS。
- “FP8 = 660 TFLOPS”：需要补条件。660.6 可以指 FP16 累加的密集峰值，也可以指 FP32 累加的结构化稀疏有效峰值。

### 输入精度与累加精度为什么要分开？

以矩阵乘累加为例：

```math
D = AB + C,\qquad
A\in\mathbb{R}^{M\times K},\quad
B\in\mathbb{R}^{K\times N},\quad
C,D\in\mathbb{R}^{M\times N}
```

每个输出元素需要沿 K 维累加多个乘积。乘法输入格式与累加器格式可以不同：例如 A、B 使用 FP16，而中间累加使用 FP32。更高的累加精度有助于减少长串求和的数值误差，但对应硬件路径的吞吐可能不同。

**FP32 累加不代表 FP32 输入乘法，累加格式也不必等于最终输出 Tensor 的存储格式。** 仅看到模型权重或输出是 FP16，仍不足以判断实际用了表中的哪一行。需要确认框架、库、计算配置和实际执行的指令。

TF32 适用于以较低乘法精度加速部分 FP32 工作负载；不能把启用 TF32 的结果与完整 FP32 乘法视为完全相同的数值计算。

### 结构化稀疏为什么不能默认乘二？

Tensor Core 的稀疏加速要求满足规定的结构，例如 2:4 模式，并通过支持该模式的编码、指令与软件路径执行。随机出现一些零，或者模型用了 MoE，都不意味着可以使用稀疏列。

尤其要区分：**MoE 按 Token 选择部分专家，是模型层面的稀疏激活；Tensor Core 的结构化稀疏，是矩阵内部的数据模式要求。** 两者不能直接互换。

## 两个可以自己算出的参数

### 为什么 FP32 峰值约为 82.6 TFLOPS？

理论估算假设全部对应运算资源每周期执行一次 FP32 FMA。一次 FMA 计算 a × b + c，按一次乘法加一次加法计为 2 FLOPs：

```math
P_{\mathrm{FP32}}
= 16384\times 2\times (2.52\times 10^9)
= 82.57536\times 10^{12}\ \mathrm{FLOP/s}
\approx 82.6\ \mathrm{TFLOPS}
```

这里算的是理想算术吞吐上限。实际 Kernel 还要执行访存、地址计算、循环与同步；依赖关系、指令混合、资源占用及实际频率都会影响吞吐。不能用这个式子推断任意 FP32 Kernel 都能达到 82.6 TFLOPS。

### 为什么显存带宽约为 1 TB/s？

21 Gbit/s 是已经包含传输机制的有效数据率，不需要再乘一次 DDR 系数：

```math
BW = \frac{384\times (21\times 10^9)}{8}
= 1008\times 10^9\ \mathrm{byte/s}
= 1008\ \mathrm{GB/s}
```

除以 8 是将 bit 转成 byte。这里指 GPU 与 GDDR6X 显存之间的理论带宽，不是 CPU 与 GPU 之间的 PCIe 带宽，也不是 L2 Cache 或 Shared Memory 的带宽。

## 后续性能分析怎样使用这些数字？

给一个 Kernel 计算“计算利用率”之前，要选择与实际计算路径匹配的峰值。例如，密集 FP16 输入、FP32 累加的 Tensor GEMM 应参考 165.2 TFLOPS，不能用 1321.2 TFLOPS 作分母。

分析显存瓶颈时，1008 GB/s 可以作为外部显存的理论带宽基准。但如果数据主要命中缓存，基于算法数据量算出的有效带宽可能超过这个数字，并不代表外部显存突破物理上限。算法字节数、实际 DRAM 传输字节数与缓存流量必须分开。

对于推理，容量影响权重、KV Cache 和临时 Buffer 能否放下；带宽影响数据搬运；算力影响计算吞吐。哪一项成为瓶颈还取决于 Batch、Shape、复用程度及 Kernel 实现，不能只靠硬件参数判断 Prefill 或 Decode 的速度。

## 面试与自测

1. **4090 有多少个 SM 和 Tensor Core？** 128 个启用的 SM；每 SM 4 个第四代 Tensor Core，合计 512 个。不要与完整 AD102 的 144 个 SM 混淆。
2. **82.6 TFLOPS 怎样计算？** CUDA Core 数 × 每周期 FMA 的 2 FLOPs × 官方 Boost Clock，得到理想 FP32 非 Tensor 峰值。
3. **为什么“4090 有 1321 TFLOPS”不足以描述推理算力？** 它省略了 FP8 输入、FP16 累加与结构化稀疏条件，也没有说明实际软件能否走到对应路径。
4. **FP16 权重意味着 FP16 累加吗？** 不意味着。输入、累加、输出存储格式需要分别确认。
5. **MoE 的稀疏激活能直接使用结构化稀疏峰值吗？** 不能。专家选择与矩阵内部规定的稀疏模式是不同条件。
6. **1 TB/s 指什么链路？** GPU 与外部显存之间的理论带宽，不是 PCIe，也不是全部存储层级的统一带宽。
