# 学习路线

目前固定学习方式和主要方向，不预设日期、篇数或完成周期。秋招是当前阶段目标，已有内容继续服务后续工作与长期积累。

## 体系化路线

| 阶段 | 学习重点 | 可形成的成果 |
| --- | --- | --- |
| 建立全景 | Token / Request 生命周期，六层关系，Prefill / Decode | 一份总览和问题清单 |
| 理解核心机制 | Attention、MLA、MoE、KV Cache、调度与指标 | 能解释公式、Shape 和设计取舍 |
| 追踪实际实现 | 选择 vLLM 或 SGLang 的一条请求路径；关联具体 Backend | 有固定版本和关键路径的源码记录 |
| 完成小实验 | Reduction、Softmax、RMSNorm，逐步进入 GEMM / Attention | 正确性检查、基线与可重复结果 |
| 分析和优化 | 系统时间线、热点 Kernel、访存与计算瓶颈 | 有指标支撑的优化结论 |
| 沉淀与扩展 | 面试追问、未解问题、项目复盘 | 可复习的专题和可延伸的项目 |

GPU 与编程基础可穿插补齐，无需读完前四层才开始 CUDA。以现有知识和实际问题决定下一步。

## 问题驱动路线

先选一个具体问题，例如“Decode 为什么慢？”：

1. 定义观察条件：模型、输入输出长度、Batch、dtype、GPU 与框架版本。
2. 查找对应原理：KV 读取、权重读取、小 M GEMM、启动开销、调度或通信。
3. 建立可测量的假设，找到源码路径或最小实验。
4. 记录证据、结论及其适用范围；尚未解释的部分保留为待研究问题。
5. 整理进对应专题，补充自测题与追问。
