**本篇的引擎**：`AI = B_M·B_N/(B_M + B_N)`——分块后的算术强度只由块的两个边决定，**B_K 与 K 都在推导中被约掉**。材料里没有这一点，是从源码读出来的。

**三处材料里没有、靠读 DeepGEMM 源码补上的硬料**：
1. `B_K` 不是调参：`block_k = 128 * 8 / get_num_element_bits(...)` → BF16 64 / FP8 128 / FP4 256，**一行恰好 128 字节**（与 `get_swizzle_mode` 的最大原子同宽）。
2. `block_m > 128 and block_n > 128` 被直接 ban（寄存器约束），且 `num_math_threads = block_m <= 64 ? 128 : 256`——行数翻倍、参与计算的线程数跟着翻倍，把每人份数压回 `B_N/2`。
3. `num_stages = (smem_capacity - smem_extra) / smem_per_stage`，上限 16、下限 3——级数是被片上容量反推出来的。
