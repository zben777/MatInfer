### 发现的三个真问题

**① 构建器遇到 GitHub 风格行内公式直接崩溃。**
`docs/01-model/attention/gqa-head-sharing.md` 第 32 行写的是 `` $`d_h`$ ``（GitHub 的 `$`…`$` 写法）。原 `inline()` 先抽 `` `code` `` 成 `\u0000N\u0000` 占位符、再匹配 `$…$`，于是**占位符被当作 TeX 喂给 MathJax** → `TypeError: Cannot read properties of null (reading '4')`。
更严重的是：**这种写法在 8 个文件里广泛使用**（gqa-from-scratch、mha-head-independence、05-kernel-engineering/README…），也就是说**除了 online-softmax，全仓库的专题都构建不了**——这解释了为什么之前只做出了一个阅读页。
修法：改成**一次扫描的三选一正则** `` `code` `` / `` $`tex`$ `` / `$tex$`，谁先出现谁生效（解决了"公式里含代码占位符"和"代码里含 `$`"两类冲突）。

**② 构建器不支持 `<details>` 折叠块。**
裸 HTML 被当普通段落转义输出。layernorm-rmsnorm.md 有 4 个、gqa-head-sharing.md 有 1 个。
修法：`parseBlocks` 按块识别 `<details>…</details>`，取出 `<summary>`，内部**递归走 Markdown 解析**；`build()` 的 switch 抽成可递归的 `renderBlocks(list, ctx, toc)`；补 `article details/summary` CSS。

**③ `docs/normalization.html` 不是纯构建产物，直接重建会退化。**
它有**手工追加的 CSS**（`details/summary`、`sup`、`li`、`@media(min-width:1600px)`、`.diagram-link:hover`）、一个额外的 `active` 侧栏项、以及不同页脚文案。所以它不能当 `managed` 页重建。
修法：只在原文件里改那 4 个 `href`（`../../../assets/` → `../assets/`），**git diff 确认只有 4 行变化**。同时在 `topics.json` 给该页与 gqa 页标 `managed: false`（只检查不覆盖）。
